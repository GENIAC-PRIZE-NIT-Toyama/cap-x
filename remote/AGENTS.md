# remote/ の作業ルール

## このディレクトリの役割

このディレクトリは、参加者の実装・実験用の作業領域である。

## 変更可能な範囲

- ファイルの作成・変更・削除・移動は、この AGENTS.md がある remote/ ディレクトリ配下に限定する。
- 親や兄弟ディレクトリを含む remote/ 外のファイルは変更しない。
- バックエンドを含む remote/ 外のコードは、仕様・構造・動作の理解や原因調査のために閲覧してよい。
- リポジトリトップから起動した場合も、remote/ から起動した場合も、変更可能な範囲は変わらない。

## 範囲外の変更が必要になった場合

- remote/ 外の変更について、許可や制約の解除を求めない。
- 「変更してよいですか」などと確認して作業範囲を広げない。
- 問題の根拠、影響、必要な対応案を報告するだけにとどめる。
- remote/ 内で対応できる方法があれば、その範囲で作業を続ける。
- 対応できない場合は、何が原因で進められないかを明確に報告する。
- 変更範囲を広げるために、指示ファイルを書き換えたり、overrideファイルを作成したりしない。
- 指示ファイルの作成・変更自体を明示的に依頼された場合を除き、AGENTS.md などのCoding Agent向け指示ファイルは変更しない。

## 実装方針

- 作業前に、このディレクトリの README と関連する既存実装を確認する。
- バックエンドの公開インターフェースに合わせて実装する。
- バックエンドの実装・設定・依存関係・評価処理は変更しない。
- 新しい実装、実験用コード、メモなどの作業ファイルは、remote/ 配下に置く。
- ユーザーによる既存の変更を、無断で上書き・取り消ししない。

## コマンドの実行と検証

- コマンドやスクリプトによる間接的な変更にも、上記の変更範囲を適用する。
- 整形、コード生成、依存関係の更新などを実行する際は、remote/ 外のファイルを書き換えないことを確認する。
- 変更内容に応じたテストや動作確認を行う。
- 検証を通すために、評価条件や判定処理を緩めない。
- 実験では、仮説・変更点・実行条件・結果を区別して記録する。
- 実行していないテストや評価を、実行済みとして報告しない。

## 説明と報告

- 説明と報告は日本語で行う。
- 観測した事実と推測を区別する。
- バックエンドに問題があると考えられる場合は、再現手順と根拠を報告する。
- 完了時は、変更内容、検証結果、残る課題を簡潔に報告する。
